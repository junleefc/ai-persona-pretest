# AI 고객 페르소나 사전검증

**내 랜딩페이지를 가상 한국인 7명에게 보여주고, 신청 버튼을 누를지 물어보는 도구**

오늘 만든 페이지를 아직 아무도 안 봤습니다. 실제 고객을 만나기 전에, 통계 데이터로 만든 가상 한국인 7명에게 먼저 보여 주세요. 7명 중 몇 명이 누르는지, 안 누르면 어느 문장에서 멈췄는지, 그 문장을 뭐라고 바꾸면 되는지가 한 장으로 나옵니다. 그리고 바로 고칩니다.

Claude 데스크탑 앱의 Code 탭에서 프롬프트 하나만 붙여넣으면 됩니다. 설치할 것도, 외울 명령어도 없습니다.

## 3단계로 끝

**Claude 데스크탑 앱의 Code 탭에서** 하세요. claude.ai 웹 채팅이나 휴대폰 앱에서는 되지 않습니다. 폴더의 파일을 읽고, 데이터를 내려받고, 리포트 파일을 만들어야 하기 때문입니다.

**모델은 Opus를 권합니다.** Sonnet으로도 되지만 두세 배 오래 걸립니다. 결과물 품질은 비슷했습니다.

준비물: 랜딩페이지를 만든 **mvp 폴더** 안에 기획서 md, PRD.md, index.html.

**1. 보여주기.** Code 탭에서 mvp 폴더를 연 뒤 붙여넣습니다.

```
https://github.com/junleefc/ai-persona-pretest
이 리포의 GUIDE.md를 읽고 그대로 진행해줘.
이 폴더에 내 기획서 md, PRD.md, index.html이 있어.
가상 한국인 7명에게 내 페이지를 보여주고 신청 버튼을 누를지 물어봐줘.
다 되면 리포트를 브라우저로 열어서 보여줘.
```

**2. 읽기.** 리포트가 열립니다. 맨 위 세 줄만 보면 됩니다. 7명 중 몇 명이 누르는지, 가장 많이 걸린 구간, 바꿀 문장 하나.

**3. 고치기.**

```
리포트 결론을 반영해서 index.html을 고쳐줘.
가장 많이 걸린 구간의 문장만 바꾸고, 나머지 내용과 디자인은 그대로 둬.
다 되면 브라우저에서 다시 열어서 보여줘.
```

이미 배포한 사이트가 있으면 주소를 주면 됩니다. 프롬프트에 `내 사이트 주소는 https://... 야. 이 페이지를 받아서 써줘.` 한 줄을 넣으세요. 기획서 md가 없어도 페이지에서 추정해 진행합니다.

**4. 반복합니다.** 한 번 돌리고 끝내면 절반만 쓴 것입니다. 검증하고, 지적받은 문장 하나를 고치고, 다시 검증하세요. 두세 번 반복하면 페이지가 눈에 띄게 달라집니다. 한 번에 한 문장씩만 고쳐야 무엇 때문에 달라졌는지 알 수 있습니다. 리포트 파일에는 날짜가 붙어 쌓이므로 처음 것과 마지막 것을 비교할 수 있습니다.

```
고친 index.html로 같은 7명에게 다시 물어봐줘.
오늘 날짜를 붙여 새 리포트로 저장하고, 지난번과 무엇이 달라졌는지 맨 위에 한 줄로 써줘.
```

세 번쯤 다듬은 뒤에는 리포트 맨 아래 질문 세 개를 들고 실제 사람 3명을 만나 보세요.

고친 페이지로 다시 물어보는 프롬프트와 막혔을 때 대처는 [PROMPT.md](PROMPT.md)에 있습니다.

## 얼마나 걸리고, 그동안 뭐가 보이나

**Opus는 6~10분, Sonnet은 15~25분 걸립니다.** 프롬프트를 보내 놓고 다른 일을 하셔도 됩니다. 결과 품질은 비슷하고 시간만 다르니 Opus를 권합니다. 아래 표는 Opus 기준입니다.

| 단계 | 시간 | 채팅창에 보이는 것 |
|---|---|---|
| 기획서와 페이지 읽기 | 30초 | 기획서에서 뽑은 여섯 가지 표 |
| 100만 명에서 조건 검색 | 1~2분 | 색인 15MB 받고, 조건에 맞는 24명 프로필을 받습니다. "100만 명 중 조건 매칭 N명"이 나옵니다 |
| 7명 고르기 | 30초 | 7명 표(이름, 나이, 지역, 직업, 고른 이유)와 "100만 명 중 조건 매칭 N명" |
| 7명 인터뷰 | 3~5분 | 가장 오래 걸립니다. 한 사람씩 답이 올라옵니다 |
| 종합과 리포트 만들기 | 1~2분 | 리포트 두 파일을 저장하고 브라우저가 열립니다 |

끝나면 mvp 폴더에 파일 세 개가 생깁니다.

- **REPORT-(날짜).html** 브라우저로 보는 리포트. 이걸 보시면 됩니다
- **REPORT-(날짜).md** 같은 내용의 글. "리포트 결론을 반영해서 고쳐줘"라고 할 때 클로드가 읽습니다
- **candidates.json** 100만 명에서 검색해 받은 후보. 둬도 되고 지워도 됩니다
- **index.tsv.gz** 100만 명 색인. 지우지 마세요. 다시 돌릴 때 씁니다

report.json이 하나 더 생기는데 리포트를 만들 때 쓴 재료입니다. 둬도 되고 지워도 됩니다.

## 무엇을 물어보나

7명 각각이 기획서와 페이지를 읽고 1인칭으로 답합니다. 질문은 한 장 기획서의 다섯 칸과 같습니다.

| 질문 | 확인하는 것 |
|---|---|
| 불편 | 기획서에 적은 불편이 이 사람에게도 있나. 마지막으로 겪은 게 언제인가 |
| 지금 방법 | 지금은 어떻게 넘기고 있나. 얼마나 귀찮은가 |
| 차이 | "내 것은 이게 다르다"가 이 사람에게 의미 있나 |
| 가격 | 그 돈을 낼 것인가. 이미 돈 내고 쓰는 게 있나 |
| 페이지 | 페이지를 위에서 아래로 읽고 **버튼을 누르나**. 안 누르면 첫 화면 / 차이 / 무료 제안 / 신청 항목 중 **어디서 멈췄나**. **뭐라고 바뀌면 누르나** |

7명 중 **5명은 기획서에 정의한 핵심 타깃**입니다. 이 5명의 답이 페이지가 통하는지를 말해 줍니다.

나머지 **2명은 조건에서 한 가지만 일부러 벗어나게** 고릅니다. 한 명은 나이가 10살쯤 위나 아래, 한 명은 직업이 다르지만 같은 불편을 겪을 법한 사람입니다. 이 2명은 페이지 평가가 아니라 **내가 정한 타깃 범위가 맞는지** 확인하는 용도입니다. 벗어난 사람도 필요하다고 하면 타깃을 넓혀도 되고, 상관없다고 하면 지금 범위가 맞습니다.

## 결과 예시

가정통신문 정리 서비스(초등 저학년 맞벌이 부모 대상, 월 4,900원)로 돌린 결과입니다. 전체는 [examples/gajeongtongsinmun](examples/gajeongtongsinmun)에 있습니다.

> **7명 중 2명이 신청 버튼을 누릅니다.** 3명은 모르겠다, 2명은 안 누른다.
>
> **가장 많이 걸린 곳: 무료 제안.** 모르겠다고 한 3명 중 2명(김준호, 주정은)이 여기서 멈췄다. 3장 보내면 무엇이 언제 오는지, 한 번인지 계속인지, 어디로 보내는지가 없다. 누른 2명도 같은 걸 걸렸다고 했다.
>
> **바꿀 문장**
> 지금: 가정통신문 3장을 보내 주시면, 일정·준비물 정리표를 만들어 하루 안에 카톡으로 보내 드립니다.
> 제안: 가정통신문 3장을 카톡으로 찍어 보내 주시면, 하루 안에 날짜별 일정·준비물 정리표를 카톡으로 돌려 드립니다.
>
> **이 7명은 어떻게 뽑았나.** 1,000,000명 → 조건 매칭 116,552명(30~45세, 배우자 있음, 자녀와 거주 (지역·성별 조건 없음)) → 프로필 수신 37명 → 7명. 인접 세그먼트 2명으로 50대 부모와 무직 부모를 따로 검색했습니다.

7명 카드 중 하나:

> **박미** 50세 여 · 경기 시흥시 · 경리 사무원 · 인접 세그먼트 · 안 누른다
> 지금 방법: 그때는 애들한테 직접 물어봤어요. 단톡방 같은 건 없었고요. 지금은 그럴 일이 없어요.
> 이렇게 바뀌면 누른다: "저한테 맞는 말은 없어요. 초등 저학년 부모라고 앞에 딱 써 두면 저 같은 사람은 헷갈리지 않고 지나갈 거예요."

## 할 수 있는 것, 없는 것

**할 수 있는 것**
- 페이지의 어느 문장이 약한지 미리 찾기
- "이런 사람은 이런 이유로 안 누른다"는 반대 시나리오 보기
- 실제 사람에게 물어볼 질문 3개 얻기

**할 수 없는 것**
- 수요가 있다고 증명하기. 가상 고객이 누른다고 해도 실제 사람이 누르는 것과 다릅니다
- 가격이 맞다고 확정하기
- 실제 인터뷰 대체하기

**결과는 전부 가설입니다.** "된다"가 아니라 "이 문장을 고치고 실제 사람 3명에게 확인하자"로 읽으세요. 리포트 끝에 그 3명에게 물어볼 질문이 있습니다.

## 데이터: 가상 한국인 100만 명

NVIDIA가 공개한 **Nemotron-Personas-Korea**를 씁니다. 통계청, 대법원, 건강보험공단 등 실제 공공 통계를 바탕으로 AI가 만든 100만 명의 가상 한국인 프로필입니다. 한 사람마다 나이, 성별, 지역, 직업, 학력, 혼인, 가구 형태, 주거 형태와 함께 직업·가족·관심사·목표를 서술한 한국어 텍스트가 있습니다. 가상 인물이라 개인정보 문제가 없습니다.

**7명은 100만 명 전체에서 찾습니다.** 100만 명의 나이·성별·지역·직업·혼인·가구 형태와 상황 태그만 담은 색인 파일(15MB)을 받아 내 컴퓨터에서 조건 검색을 하고, 조건에 맞는 사람 중 무작위 24명의 전체 프로필을 HuggingFace에서 받아옵니다. 다운로드 15MB, 설치 없음, API 키 없음. 조건에 맞는 전체 인원(예: "건축자재 영업원 30~55세 남성 91명")이 리포트의 선별 메모에 적힙니다.

왜 전체에서 찾나: 레미콘 영업, 임업인, 묘목 생산자처럼 좁은 타깃은 표본을 줄이면 사라집니다. 100만 명에는 건축자재 영업원이 168명, 임업 관련이 202명 있지만 1만 명으로 줄이면 0~2명입니다. 타깃이 아닌 사람에게 물으면 당연히 안 누르고, 그 답은 페이지 문제가 아니라 사람을 잘못 데려온 것입니다. 직업은 2,120종으로 세분돼 있어 대부분의 타깃을 직업으로 잡을 수 있고, 수험생이나 육아처럼 직업이 아닌 상황은 열여섯 개 상황 태그로 잡습니다.

HuggingFace 접속이 안 될 때만 리포에 넣어 둔 [personas.jsonl](personas.jsonl)을 씁니다. 13,798명(31MB)이고, 2,120개 직업이 하나도 빠짐없이 들어가도록 직업마다 최대 4명씩 넣은 뒤 인구 비례 표본을 더한 것입니다. 그래서 드문 직업도 몇 명은 남아 있습니다.

| 항목 | 내용 |
|---|---|
| 제작 | NVIDIA |
| 원본 | [huggingface.co/datasets/nvidia/Nemotron-Personas-Korea](https://huggingface.co/datasets/nvidia/Nemotron-Personas-Korea), 100만 명 |
| 라이선스 | CC BY 4.0 |
| 검색 방식 | 색인 파일(index.tsv.gz, 100만 명)로 로컬 검색 후 HuggingFace rows API로 프로필 수신 |
| 대체 파일 | personas.jsonl 13,798명, 2,120개 직업 전부 포함 (접속 실패 시) |
